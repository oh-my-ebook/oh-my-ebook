# Ebook 책장

**작성일**: 2026-09-16  
**상태**: 초안

## 개요

사용자는 로그인 없이 브라우저에 PDF를 업로드하고, 업로드한 자료를 책장 형태의 화면에서
관리한다. 각 책은 PDF 첫 페이지를 표지로 사용하며 제목, 지은이, 출판사와 읽은 페이지를 함께
표시한다. 포인터를 올리거나 움직이면 표지가 절제된 3D 움직임으로 반응한다.

PDF 원본, 표지, 서지 정보와 독서 진행률은 SQLite WASM과 OPFS를 이용해 현재 브라우저 프로필의
현재 출처(origin)에 저장한다. 서버 계정이나 원격 저장소는 사용하지 않는다.

  허용되지 않으면 업로드를 막는다. 저장소 사용량과 예상 잔여 할당량을 표시하고 사용자가 책별

  제한 없이 예상 잔여 할당량이 부족하면 업로드를 거부한다.
- Q: 같은 책장을 여러 탭에서 사용할 때 진행률과 목록을 어떻게 동기화할까요? → A: 다중 탭을
  허용하고 마지막으로 성공적으로 저장된 페이지를 최종 독서 위치로 사용한다. 책장에는 수동
  새로고침을 제공하고 작업 직전에 최신 데이터를 확인한다.
- Q: 한 탭에서 읽는 책을 다른 탭에서 삭제하면 열린 Reader를 어떻게 처리할까요? → A: 현재
  독서는 탭을 벗어날 때까지 허용하되 삭제 상태를 알리고 진행률을 더 저장하지 않는다.
- Q: 이번 Ebook 책장 기능에 백업 내보내기와 가져오기를 포함할까요? → A: 백업 내보내기와
  가져오기를 이번 기능에서 제외한다.

### 제외 범위

- 로그인, 사용자 계정, 서버 업로드, 기기 간 동기화와 백업.
- EPUB 등 PDF가 아닌 전자책 형식.
- 제목·지은이·출판사의 직접 편집과 외부 서지 정보 조회.
- 책 검색, 정렬, 분류, 태그와 폴더.
- 여러 책의 일괄 삭제. PDF 원본, 표지, 메타데이터와 진행률의 백업 내보내기·가져오기.
- 독서 화면 자체의 보기 방식, 탐색과 렌더링 동작. 책 선택 후의 독서 경험은 기본 PDF Reader
  명세를 따른다.

## 사용자 시나리오

### 사용자 스토리 1: PDF를 내 책장에 추가한다 (P1)

사용자는 기기에 있는 PDF를 선택해 책장에 추가한다. 앱은 파일을 브라우저 로컬 저장소에 보관하고
첫 페이지로 표지를 만든 뒤 책장에 표시한다.

**우선순위 근거**: 책을 추가하고 다시 찾을 수 있어야 책장과 독서 진행률이 의미를 갖는다.

**독립 검증**: 빈 책장에서 유효한 PDF 한 개를 업로드하고 표지와 기본 서지 정보가 있는 책 항목이
나타나는지 확인한다.

**인수 시나리오**:

1. **Given** 빈 책장이 열려 있다, **When** 사용자가 유효한 PDF를 선택한다, **Then** 업로드 진행
   상태를 거쳐 첫 페이지 표지와 책 정보가 있는 항목이 책장에 추가된다.
2. **Given** PDF 메타데이터에 제목·지은이·출판사가 있다, **When** 업로드가 완료된다, **Then** 책
   하단에 해당 서지 정보가 표시된다.
3. **Given** 일부 서지 정보가 없는 PDF다, **When** 업로드가 완료된다, **Then** 제목은 확장자를 뺀
   파일명으로 대체하고 없는 지은이·출판사는 각각 정보가 없다고 표시한다.
4. **Given** PDF가 아닌 파일 또는 읽을 수 없는 PDF를 선택했다, **When** 파일 검증이나 처리가
   실패한다, **Then** 실패 이유와 재시도 방법을 안내하고 책장에는 불완전한 항목을 남기지 않는다.

---

### 사용자 스토리 2: 저장된 책과 독서 진행률을 확인한다 (P1)

사용자는 책장에 들어오자마자 이전에 업로드한 책들을 보고, 각 책에서 마지막으로 읽은 페이지와
전체 페이지 수를 확인한다. 책을 선택하면 해당 PDF를 읽을 수 있다.

**우선순위 근거**: 새로고침하거나 브라우저를 다시 열어도 자료와 읽던 위치를 찾는 것이 로컬
책장의 핵심 가치다.

**독립 검증**: 저장된 PDF의 특정 페이지까지 읽은 상태를 만든 뒤 페이지를 새로 열어 같은 책,
표지, 서지 정보와 진행률이 복원되는지 확인한다.

**인수 시나리오**:

1. **Given** 이전에 업로드한 책이 있다, **When** 같은 브라우저 프로필과 출처에서 책장에 다시
   접근한다, **Then** 원본 PDF를 다시 선택하지 않아도 책과 저장된 정보가 표시된다.
2. **Given** 아직 열지 않은 책이다, **When** 책장을 확인한다, **Then** 읽지 않음 상태와 전체
   페이지 수가 표시된다.
3. **Given** 마지막으로 12페이지를 읽은 100페이지 책이다, **When** 책장을 확인한다, **Then**
   `12 / 100 페이지`와 이에 해당하는 진행 상태가 표시된다.
4. **Given** 저장된 책을 선택했다, **When** PDF Reader가 열린다, **Then** 마지막으로 성공적으로
   저장된 페이지부터 시작하고 이후 유효한 현재 페이지가 바뀔 때 책장의 진행률에 반영된다.

---

### 사용자 스토리 3: 책장처럼 책을 둘러본다 (P2)

사용자는 반응형 책장에 배열된 표지를 훑어보고, 포인터가 있는 환경에서는 책을 살짝 돌려 입체감을
확인한다. 키보드나 터치 환경에서도 같은 책 정보와 선택 기능을 이용한다.

**우선순위 근거**: 책장다운 시각 경험은 제품의 개성을 만들지만 PDF 보관과 재접근보다 우선하지
않는다.

**독립 검증**: 포인터, 키보드, 터치와 동작 감소 설정에서 같은 책 항목을 탐색하고 열 수 있으며
필요한 정보가 유지되는지 확인한다.

**인수 시나리오**:

1. **Given** 정밀 포인터를 사용하는 환경이다, **When** 사용자가 표지 위에서 포인터를 움직인다,
   **Then** 포인터 위치에 따라 표지가 제한된 각도 안에서 부드럽게 회전하고 포인터가 벗어나면
   원래 위치로 돌아온다.
2. **Given** 키보드 또는 터치만 사용하는 환경이다, **When** 사용자가 책을 탐색하고 선택한다,
   **Then** 3D 움직임 없이도 표지, 책 정보, 진행률과 열기 동작을 모두 이용할 수 있다.
3. **Given** 운영체제에서 동작 감소를 설정했다, **When** 사용자가 책 항목에 포인터를 올린다,
   **Then** 3D 회전과 복귀 애니메이션을 적용하지 않는다.
4. **Given** 화면 폭이 320px이거나 브라우저가 200% 확대 상태다, **When** 책장을 탐색한다,
   **Then** 책 항목과 조작부가 겹치거나 가로로 잘리지 않는다.

---

### 사용자 스토리 4: 필요 없는 책을 삭제한다 (P2)

사용자는 더 이상 보관하지 않을 책을 선택해 책장과 브라우저 로컬 저장소에서 삭제한다.

**우선순위 근거**: 로컬 저장 공간은 제한되어 있으므로 사용자가 저장한 자료를 직접 정리할 수
있어야 한다.

**독립 검증**: 저장된 책 한 권을 삭제하고 확인한 뒤 목록, 원본 PDF, 표지, 서지 정보와 진행률이
함께 제거되는지 확인한다.

**인수 시나리오**:

1. **Given** 책장에 저장된 책이 있다, **When** 사용자가 삭제를 요청한다, **Then** 앱은 대상 책
   제목과 로컬 데이터가 삭제된다는 내용을 확인받는다.
2. **Given** 삭제 확인 창이 열려 있다, **When** 사용자가 취소한다, **Then** 책과 관련 데이터를
   그대로 유지하고 원래 조작 위치로 포커스를 돌린다.
3. **Given** 사용자가 삭제를 확인했다, **When** 삭제가 완료된다, **Then** 해당 책과 원본 PDF,
   표지, 서지 정보, 진행률이 제거되고 다른 책은 유지된다.

### 경계 조건

- 1페이지 PDF도 첫 페이지를 표지로 사용하며 전체 페이지 수를 1로 표시한다.
- 세로, 가로, 정사각형 또는 회전 정보가 있는 첫 페이지도 원본 비율과 회전을 반영한 표지를 만든다.
- 암호가 필요하거나 손상되어 페이지 수 또는 첫 페이지를 읽을 수 없는 PDF는 저장하지 않고 이유를
  안내한다.
- 같은 내용의 PDF를 다시 선택하면 중복임을 안내하고 기존 책을 유지한다. 파일명만 같고 내용이
  다른 PDF는 별도 책으로 저장한다.
- 여러 파일을 한 번에 선택하면 각 파일을 독립적으로 처리한다. 일부 파일이 실패해도 성공한 파일은
  저장하고 파일별 결과를 알린다.
- 저장 공간이 부족하거나 OPFS·SQLite 초기화 또는 쓰기가 실패하면 원인을 알 수 있는 오류와
  재시도를 제공하며, 원본과 메타데이터가 일부만 남은 책은 목록에 표시하지 않는다.
- PDF 파일에는 고정 크기 제한을 두지 않는다. 업로드 직전 파일 크기가 예상 잔여 할당량보다 크면
  해당 파일을 처리하지 않고 필요한 공간과 예상 잔여 공간을 안내한다.
- 표지 생성이 일시적으로 실패하면 기본 표지를 사용해 원본 PDF와 서지 정보는 보존하고 표지
  재생성을 시도할 수 있게 한다.
- 브라우저 데이터가 삭제되거나 시크릿 모드 세션이 끝나면 자료를 복구할 수 없음을 첫 업로드 전에
  안내한다.
- 다른 브라우저, 다른 브라우저 프로필, 다른 기기 또는 다른 출처에서는 저장된 책이 보이지 않는다.
- 여러 탭에서 같은 책을 읽으면 마지막으로 성공적으로 커밋된 페이지를 최종 독서 위치로 사용한다.
  탭 종료 이벤트만으로 저장 완료를 판단하지 않는다.
- 한 탭에서 삭제한 책이 다른 탭의 오래된 목록에 남아 있더라도 열기나 삭제를 실행하기 전에 최신
  저장 상태를 확인하고, 이미 삭제된 책이라고 안내한다.
- 다른 탭에서 이미 열어 메모리에 불러온 책이 삭제되면 현재 Reader는 탭을 벗어날 때까지 표시할 수
  있다. 삭제를 감지한 뒤에는 진행률을 저장하거나 책 데이터를 다시 만들지 않는다.

## 기능 요구사항

### 책장 진입과 업로드

- **FR-001**: 사용자가 책장에 접근하면 저장된 책 목록을 불러오며, 불러오는 동안 상태를 표시하고
  목록 조작을 비활성화한다.
- **FR-002**: 저장된 책이 없으면 빈 상태, PDF 선택 동작과 로컬 저장 범위 및 데이터 삭제 가능성을
  안내한다.
- **FR-003**: 파일 선택기로 하나 이상의 PDF를 선택해 업로드할 수 있어야 한다. 파일 선택 동작에는
  접근 가능한 이름이 있어야 한다.
- **FR-004**: 각 선택 파일이 PDF인지 확인하고, 페이지 수와 첫 페이지를 읽을 수 있을 때만 저장
  가능한 문서로 처리한다.
- **FR-005**: 여러 파일은 서로 독립적으로 처리하고 파일별 진행 상태와 성공 또는 실패 결과를
  제공해야 한다. 한 파일의 실패가 다른 파일의 저장을 취소하면 안 된다.
- **FR-006**: 동일한 PDF 내용이 이미 저장되어 있으면 새 항목을 만들지 않고 기존 책을 식별할 수
  있게 안내해야 한다. 파일명만으로 중복을 판단하면 안 된다.

### 표지와 서지 정보

- **FR-007**: PDF의 회전 정보를 적용한 첫 페이지 전체를 원본 비율로 렌더링해 책 표지 이미지를
  만들어야 하며, 표지 때문에 PDF 원본을 변경하면 안 된다.
- **FR-008**: 표지 생성에 실패해도 원본 PDF가 유효하면 기본 표지로 책을 저장하고, 실패 상태와
  표지 재생성 동작을 제공해야 한다.
- **FR-009**: PDF 메타데이터에서 제목과 지은이를 읽고, 출판사는 PDF 메타데이터의 발행 주체
  정보가 있을 때 사용해야 한다.
- **FR-010**: 제목이 없으면 확장자를 뺀 파일명을 사용하고, 지은이 또는 출판사가 없으면 각 항목에
  `정보 없음`을 표시해야 한다. 비어 있거나 공백뿐인 메타데이터는 없는 값으로 처리한다.
- **FR-011**: 각 책 항목은 표지 하단에 제목, 지은이, 출판사와 독서 진행률을 표시해야 한다. 긴
  정보는 책장 배치를 깨뜨리지 않아야 하며 전체 값에 접근할 방법을 제공해야 한다.

### 로컬 저장과 복원

- **FR-012**: PDF 원본, 표지, 서지 정보, 전체 페이지 수, 마지막으로 읽은 페이지와 저장 식별자를
  SQLite WASM과 OPFS를 사용해 현재 브라우저 프로필의 현재 출처에 저장해야 한다. 첫 업로드 전에
  앱 자체 확인창 없이 브라우저에 영구 저장을 요청하며, 브라우저가 표시하는 권한 UI는 그대로
  제공해야 한다.
- **FR-013**: 앱을 새로고침하거나 브라우저를 닫았다가 다시 열어도 브라우저 데이터가 유지된 경우
  저장된 책, 표지, 서지 정보와 진행률을 복원해야 한다.
- **FR-014**: 원본 PDF와 해당 데이터의 저장을 하나의 완료 단위로 다뤄야 한다. 저장 실패나 중단
  후 원본 또는 메타데이터만 남은 항목을 책장에 표시하면 안 된다.
- **FR-015**: OPFS 또는 필요한 브라우저 기능을 사용할 수 없거나 영구 저장이 허용되지 않으면
  이유를 알리고 업로드를 비활성화해야 한다. 일반 저장으로 전환하거나 이미 확인할 수 있는
  데이터를 임의로 삭제하면 안 된다.
- **FR-016**: 저장 공간 부족, 데이터베이스 초기화 실패, 읽기 실패와 쓰기 실패를 구분해 안내하고
  가능한 작업에는 재시도를 제공해야 한다.
- **FR-017**: 첫 업로드 전에 자료가 서버나 다른 기기에 동기화되지 않으며, 영구 저장 상태여도
  사용자가 브라우저 데이터를 삭제하면 함께 사라질 수 있음을 알려야 한다.

### 독서 진행률과 책 열기

- **FR-018**: 읽지 않은 책에는 `읽지 않음`과 전체 페이지 수를 표시해야 한다. 읽은 책에는 마지막으로
  읽은 PDF 페이지와 전체 PDF 페이지 수를 `현재 / 전체 페이지` 형식으로 표시해야 한다.
- **FR-019**: 진행률은 표지를 포함한 PDF 파일 페이지 번호를 사용하며 1부터 전체 페이지 수 사이의
  정수여야 한다. 인쇄 쪽수나 진행률 백분율을 원본 값으로 저장하면 안 된다.
- **FR-020**: 책을 선택하면 저장된 PDF를 Reader에서 열고, 유효한 마지막 읽은 페이지가 있으면
  해당 페이지부터, 없으면 1페이지부터 시작해야 한다.
- **FR-021**: Reader의 유효한 현재 페이지가 바뀌면 탭 종료를 기다리지 않고 해당 책의 마지막으로
  읽은 페이지를 로컬에 저장해야 한다. 빠른 연속 이동은 마지막 위치가 누락되지 않는 범위에서
  저장을 합칠 수 있다. 쓰기 실패 시 현재 독서를 중단시키지 않고 진행률을 저장하지 못했음을
  알려야 한다.
- **FR-022**: 저장된 마지막 페이지가 전체 페이지 수 범위를 벗어나면 1페이지로 복구하고 잘못된
  값을 로컬 데이터에 남기지 않아야 한다.

### 책장 표현과 상호작용

- **FR-023**: 저장된 책을 반응형 책장 형태로 배열하고, 각 책의 표지와 하단 정보를 하나의
  항목으로 인식할 수 있게 표시해야 한다.
- **FR-024**: 정밀 포인터가 표지 위에서 움직이면 포인터 위치에 따라 가로·세로 회전이 변하는 3D
  효과를 제공하고, 표지를 읽기 어렵거나 인접 항목과 겹치지 않는 제한된 각도 안에서 움직여야
  한다. 포인터가 벗어나면 원래 위치로 돌아와야 한다.
- **FR-025**: 동작 감소 설정에서는 3D 회전과 복귀 애니메이션을 제거해야 한다. 터치와 키보드
  환경에서는 3D 조작 없이도 모든 정보와 동작을 제공해야 한다.
- **FR-026**: 책 선택과 삭제는 키보드로 조작할 수 있고, 보이는 포커스와 접근 가능한 이름을
  제공해야 한다. 상태와 진행률은 색이나 시각 효과에만 의존하면 안 된다.
- **FR-027**: 320px 화면 폭과 브라우저 200% 확대에서도 책 정보와 조작부가 겹치거나 가로로
  잘리지 않아야 한다.

### 삭제

- **FR-028**: 각 책에 삭제 동작을 제공하고 실행 전에 대상 책 제목, 삭제 범위와 복구할 수 없음을
  확인받아야 한다.
- **FR-029**: 삭제를 확인하면 해당 책의 PDF 원본, 표지, 서지 정보와 진행률을 함께 삭제하고 다른
  책의 데이터는 유지해야 한다.
- **FR-030**: 삭제를 취소하면 데이터를 변경하지 않고 삭제 동작을 시작한 요소로 포커스를
  복원해야 한다. 삭제 실패 시 책을 목록에서 제거한 것처럼 표시하지 말고 재시도를 제공해야 한다.

### 저장 공간 관리

- **FR-031**: 책장에 현재 출처가 사용하는 저장 용량과 브라우저가 제공하는 예상 할당량을 표시하고,
  두 값의 차이로 예상 잔여 할당량을 표시해야 한다. 브라우저가 값을 추정치로 제공한다는 사실을
  함께 알려야 한다.
- **FR-032**: 업로드 완료, 책 삭제 또는 저장 실패 후 저장 용량 정보를 다시 조회해야 한다. 조회에
  실패해도 저장된 책의 열람과 삭제를 막지 말고 용량 정보를 확인할 수 없다고 안내해야 한다.
- **FR-033**: 사용자가 용량을 확인한 뒤 책별 삭제 동작으로 해당 PDF와 관련 데이터를 제거하고
  공간을 회수할 수 있어야 한다. 삭제가 완료되면 갱신된 예상 사용량과 잔여 할당량을 표시해야
  한다.
- **FR-034**: PDF 한 파일의 고정 크기 제한을 두면 안 된다. 각 파일을 저장하기 직전에 최신 예상
  잔여 할당량을 조회하고 파일 크기가 이를 초과하면 해당 파일의 업로드를 거부해야 한다. 예상
  잔여 할당량이 충분해도 실제 저장이 실패할 수 있으므로 FR-014와 FR-016의 실패 처리를 유지해야
  한다.
- **FR-035**: 같은 브라우저 프로필과 출처에서 여러 탭이 책장과 Reader를 동시에 사용하는 것을
  허용해야 한다. 같은 책의 진행률을 여러 탭이 저장하면 마지막으로 성공적으로 커밋된 페이지를
  최종 독서 위치로 사용해야 한다.
- **FR-036**: 책장에 새로고침 동작을 제공하고, 실행하면 저장소에서 책 목록, 서지 정보, 진행률과
  용량 정보를 다시 읽어 현재 화면을 교체해야 한다. 실패하면 기존 화면을 유지하고 재시도를
  제공해야 한다.
- **FR-037**: 오래된 탭에서 책 열기나 삭제를 실행하기 직전에 해당 책의 최신 존재 여부를
  확인해야 한다. 다른 탭에서 이미 삭제한 책이면 작업을 실행하지 않고 삭제된 PDF임을 안내해야
  한다.
- **FR-038**: DB 잠금이나 동시 쓰기로 진행률 또는 목록 변경이 즉시 완료되지 않으면 제한된
  범위에서 재시도해야 한다. 최종 실패 시 다른 탭의 사용 가능성을 포함한 오류를 안내하고 성공한
  것처럼 화면을 갱신하면 안 된다.
- **FR-039**: 열린 Reader가 진행률을 저장하려는 시점에 다른 탭에서 해당 책이 삭제된 사실을
  확인하면 삭제 상태를 안내하고 이후 진행률 저장을 중단해야 한다. 이미 메모리에 불러온 PDF는
  현재 탭이 Reader를 벗어날 때까지 계속 표시할 수 있지만, 삭제된 책이나 관련 데이터를 다시
  만들면 안 된다.

### 주요 데이터

- **책**: 저장된 PDF 한 권을 나타낸다. 저장 식별자, 내용 중복 판별값, 원본 파일명, 제목, 지은이,
  출판사, 전체 페이지 수, 표지 상태와 생성 시각을 가진다.
- **PDF 원본**: 사용자가 선택한 파일의 바이트 데이터다. 책 한 권에 하나가 연결되며 서버로
  전송하지 않는다.
- **표지**: PDF 첫 페이지에서 생성한 이미지 또는 생성 실패 시의 기본 표지다. 책 한 권에 하나가
  연결된다.
- **독서 진행률**: 책별 마지막으로 읽은 PDF 페이지와 갱신 시각이다. 아직 읽지 않은 책에는 마지막
  페이지 값이 없다.

## 완료 기준

- **SC-001**: 유효한 PDF 1개와 여러 PDF를 선택하는 시나리오에서 성공한 파일은 모두 책장에
  나타나고, 실패한 파일은 불완전한 책을 남기지 않으며 파일별 결과를 확인할 수 있다.
- **SC-002**: 메타데이터가 모두 있는 PDF와 일부 또는 전부 없는 PDF에서 표지, 제목, 지은이,
  출판사와 전체 페이지 수가 FR-007~FR-011의 규칙대로 표시된다.
- **SC-003**: 책을 업로드한 뒤 페이지 새로고침과 브라우저 재시작을 거쳐도 같은 브라우저 프로필과
  출처에서 원본을 다시 선택하지 않고 책을 열 수 있다.
- **SC-004**: 100페이지 책을 12페이지까지 읽은 뒤 책장으로 돌아오거나 다시 접속하면
  `12 / 100 페이지`가 표시되고, 책을 다시 열면 12페이지부터 시작한다.
- **SC-005**: 동일 내용의 중복 파일, 손상된 PDF, 암호가 필요한 PDF, 표지 생성 실패, 저장 공간
  부족과 저장소 초기화 실패를 각각 검증하며 데이터가 부분 저장되거나 기존 책이 손상되지 않는다.
- **SC-006**: 정밀 포인터에서 표지가 제한된 3D 각도로 반응하고 원위치로 돌아온다. 터치,
  키보드와 동작 감소 설정에서는 효과 없이 동일한 정보 확인, 책 열기와 삭제를 완료할 수 있다.
- **SC-007**: 320px 화면 폭과 브라우저 200% 확대에서 책장 탐색, 업로드, 책 열기와 삭제 확인을
  수행할 수 있고 콘텐츠나 조작부가 겹치거나 가로로 잘리지 않는다.
- **SC-008**: 책 한 권을 삭제하면 해당 원본, 표지, 서지 정보와 진행률이 다시 나타나지 않으며
  나머지 책은 그대로 유지된다.
- **SC-009**: 영구 저장이 허용된 환경에서는 업로드를 진행하고, 거부되거나 지원되지 않는
  환경에서는 일반 저장으로 전환하지 않고 업로드를 막는다. 업로드와 책 삭제 전후에 사용량과 예상
  잔여 할당량이 갱신되며 용량 조회 실패가 기존 책의 열람이나 삭제를 막지 않는다.
- **SC-010**: 크기가 예상 잔여 할당량 이하인 PDF는 고정 크기 제한 없이 저장을 시도하고, 예상
  잔여 할당량을 초과하는 PDF는 저장을 시작하지 않는다. 사전 확인을 통과한 뒤 실제 저장이
  실패해도 불완전한 책을 남기지 않는다.
- **SC-011**: 두 탭에서 같은 책의 서로 다른 페이지를 저장하면 마지막으로 성공한 커밋의 페이지가
  다음 Reader 시작 위치로 사용된다. 한 탭에서 책을 삭제한 뒤 다른 탭의 오래된 목록에서 해당
  책을 열거나 삭제하려 하면 삭제된 PDF임을 안내하며, 수동 새로고침 후 목록과 진행률이 최신 저장
  상태와 일치한다.
- **SC-012**: 한 탭의 Reader에서 연 책을 다른 탭에서 삭제하면 열린 Reader는 다음 진행률 저장 시
  삭제 상태를 알리고 저장을 중단한다. 현재 탭을 벗어날 때까지 메모리에 불러온 PDF를 읽을 수
  있지만 이후 책장 새로고침이나 재접속에서 해당 책이 다시 나타나지 않는다.

## 가정

- 로그인 없는 `사용자별 저장`은 계정 단위가 아니라 현재 브라우저 프로필과 출처 단위의 로컬
  저장을 뜻한다.
- 영구 저장 요청의 승인 방식은 브라우저가 결정한다. 앱은 별도 확인창을 표시하지 않지만
  브라우저가 자체 권한 UI를 표시할 수 있다.
- 지원 브라우저는 SQLite WASM과 OPFS에 필요한 기능을 제공하는 최신 데스크톱·모바일 브라우저로
  한정한다. 구체적인 지원 범위는 계획 단계에서 정한다.
- PDF의 표준 메타데이터에 출판사를 위한 단일 필수 필드가 없으므로, 사용 가능한 발행 주체 정보를
  출판사로 표시한다. 해당 값이 없으면 `정보 없음`을 사용한다.
- PDF Reader는 저장된 PDF 바이트와 시작 페이지를 받아 열 수 있고, 현재 페이지 변경을 책장
  기능에 전달하도록 기존 기능과 연결한다.
- 업로드는 사용자가 파일 선택기로 고른 로컬 PDF를 앱의 저장소에 복사하는 동작이며 서버 전송을
  뜻하지 않는다.
