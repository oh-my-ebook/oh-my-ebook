# 보조 패널 채팅

## 개요

`basic-pdf-reader`가 만든 함께 읽기 패널에 질문·답변 채팅 UI를 채운다. 사용자는 현재 읽고 있는 PDF 페이지에 대해 질문을 입력하고, 응답을 스트리밍으로 확인할 수 있다. 넓은 화면에서는 패널 너비를 조절하고, 좁은 화면에서는 Sheet로 열며 기존 열기·닫기·포커스 복원 동작을 유지한다.

- Q: 이번 기능에서 실제 AI 백엔드(LLM API)와 연동까지 구현 범위에 포함하나요, 아니면 UI·스트리밍 동작만 구현하고 응답은 Mock/자리표시자로 대체하나요? → A: UI·스트리밍 동작만 구현한다. 응답 생성은 Mock/자리표시자로 대체하고, 실제 AI 백엔드 연동은 이번 기능 범위에서 제외한다.
- Q: 페이지 본문(텍스트)을 채팅 컨텍스트로 전달하지 않는다는 결정이 이번 기능에서 최종 확정 사항인가요, 아니면 plan.md 단계에서 다시 바뀔 수 있는 열린 사항인가요? → A: 최종 확정한다. 이번 기능은 페이지 번호만 전달하며, 페이지 본문 전달 여부는 실제 AI 백엔드 연동을 다루는 향후 별도 기능에서 재검토한다.
- Q: 채팅 UI를 기존 shadcn(Base UI) 컴포넌트로 직접 구현할지, 아니면 assistant-ui 같은 채팅 UI 라이브러리를 도입할지? → A: assistant-ui를 도입한다. assistant-ui의 `ChatModelAdapter`(로컬 함수 기반 스트리밍)를 이용해 Mock 응답을 구현하고, 향후 실제 AI 백엔드(web-llm) 연동 시 같은 인터페이스로 교체한다. 이에 따라 필수 의존성인 `zustand`(상태 관리 라이브러리) 도입을 허용한다.

### Session 2026-09-19

- Q: 실제 AI 백엔드 연동 이후에도 질문에는 페이지 번호만 전달하나요? → A: 아니다. 저장된 도서 메타데이터와 전송 시점에 보고 있는 페이지의 PaddleOCR·Kiwi 후처리 본문을 모델 컨텍스트에 함께 전달한다. 선택 영역과 추천 질문, RAG 검색, 토큰 예산 조정은 별도 작업으로 진행한다.

### Session 2026-09-20

- Q: PDF에서 선택한 문장을 어떤 방식으로 질문에 사용하나요? → A: 선택 영역 가까이에 `채팅에 추가`와 `자세히 설명`을 표시한다. `채팅에 추가`는 인용문만 입력창에 첨부하고, `자세히 설명`은 인용문과 미리 정한 설명 프롬프트를 바로 전송한다. 선택하거나 첨부한 인용문이 없는 새 대화에는 `이 페이지 요약` 질문 칩을 표시한다.

### 제외 범위

- `이 페이지 요약` 외의 고정·동적 추천 질문.
- 대화 내용의 영구 저장, 로그인, 서버 저장. 새로고침하면 초기화한다.
- PDF 검색·인덱싱. 현재 페이지 본문은 기존 OCR 결과를 전달하지만, 다른 페이지나 문서는 검색하지 않는다.
- 페이지 본문의 토큰 예산 조정. RAG 컨텍스트 계약이 정해지기 전까지 현재 페이지의 추출 텍스트 전체를 전달한다.
- 여러 문서·여러 세션에 걸친 질문. 현재 열려 있는 한 문서, 한 번의 열람 세션으로 범위를 한정한다.
- 노트 작성·저장, 답변 편집·북마크.
- 음성 입력, 첨부파일 업로드.
- 실제 AI 백엔드/API 연동(모델 호출, 인증, 인프라 구성). 이번 기능은 UI·스트리밍 동작 검증에 집중하며 응답 생성은 Mock/자리표시자로 구현한다.

## 기능 요구사항

- **FR-001**: 보조 패널이 열려 있을 때 채팅 UI(질문 입력, 전송, 대화 내역)를 표시한다. 패널을 닫으면 채팅 UI도 함께 사라지며 진행 중이던 요청은 화면에 반영하지 않는다.
- **FR-002**: 질문 입력은 Enter로 전송하고 Shift+Enter로 줄바꿈한다. 빈 값이나 공백만 있는 입력은 전송하지 않는다.
- **FR-003**: 전송한 질문과 응답을 대화 내역에 순서대로 쌓아 표시한다. 응답은 도착하는 조각을 이어 붙여 스트리밍으로 표시하며, 완료되면 스트리밍 상태를 해제한다.
- **FR-004**: 응답을 받는 동안 로딩 상태를 표시하고 새 질문 전송을 비활성화한다. 응답 생성에 실패하면 오류를 안내하고 같은 질문을 다시 보낼 수 있는 재시도를 제공한다.
- **FR-005**: 질문에는 전송 시점에 화면에 표시 중인 PDF 페이지 번호를 함께 전달한다. 페이지를 이동해도 기존 대화 내역은 유지되며, 새로 보낸 질문은 이동한 시점의 현재 페이지를 기준으로 처리한다.
- **FR-006**: 대화 내역은 패널을 닫거나 페이지를 새로고침하면 초기화한다. 별도의 영구 저장소에 기록하지 않는다.
- **FR-007**: 질문 입력·전송·재시도 조작부에 접근 가능한 이름과 키보드 조작(Tab 이동, Enter 전송)을 제공하며 포커스가 보여야 한다. 스트리밍 중인 응답의 갱신과 완료는 보조 기술로도 확인할 수 있어야 한다.
- **FR-008**: 넓은 화면의 옆 패널과 좁은 화면의 Sheet 모두에서 채팅 조작부가 잘리거나 겹치지 않아야 한다. 대화 내역이 길어지면 채팅 영역 안에서만 스크롤한다.
- **FR-009**: 질문에는 저장된 도서 메타데이터와 전송 시점에 화면에 표시 중인 PDF 페이지의 PaddleOCR·Kiwi 후처리 본문을 함께 전달한다. 메타데이터는 값이 있는 제목·저자·주제·키워드·출판사만 포함한다. 페이지를 이동하면 이후 질문에는 이동한 페이지의 본문을 전달하며, OCR에 실패하거나 본문이 없는 페이지에서도 질문은 보낼 수 있어야 한다.
- **FR-010**: 모델에는 한국어로 답하고, 분량이 부족하면 세부사항을 생략하더라도 마지막 문장을 완결하도록 영어로 지시한다.
- **FR-011**: 사용자가 한 PDF 페이지의 OCR 텍스트를 선택하면 선택 영역 가까이에 `채팅에 추가`와 `자세히 설명` 동작을 표시한다. `채팅에 추가`는 선택 문장을 제거 가능한 인용문으로 입력창에 누적하되 질문을 보내지 않는다. 여러 인용문은 입력창 위에서 일정한 크기의 블록으로 표시하고, 공간이 부족하면 다음 줄로 넘긴다. 각 인용문은 따로 제거할 수 있다. `자세히 설명`은 첨부한 모든 인용문과 사전 정의된 설명 요청을 함께 전송한다.
- **FR-012**: 대화를 시작하기 전이고 첨부한 인용문이 없으면 assistant-ui Suggestion으로 `이 페이지 요약`을 표시한다. 선택하면 대화에는 `이 페이지에 대해 요약해줘`만 표시하고, 모델에는 현재 페이지를 줄글 3문장으로 요약한 뒤 본문에서 찾은 핵심 개념을 최대 5개 불렛포인트로 정리하라는 상세 지시문을 전달한다.
- **FR-013**: 모델 준비 상태는 준비 시작·다운로드·저장된 모델의 GPU 로딩·GPU 실행 준비를 한국어로 구분한다. 진행률은 현재 단계 기준이며, 라이브러리가 제공하는 파일 수와 처리 용량도 표시한다. 앱 시작 시 모델 가중치 전체가 캐시에 있으면 기존 엔진 준비 함수를 통해 미리 GPU에 올린다. 캐시가 없거나 불완전하면 자동 다운로드하지 않고 사용자 요청을 기다린다. 자동 준비와 수동 요청이 겹쳐도 엔진은 한 번만 생성하며, 준비 실패 후 수동 재시도를 제공한다.
- **FR-014**: RAG 검색 결과를 사용한 답변은 생성이 끝난 뒤 맨 끝에 페이지별 인용 출처를 인라인 배지로 표시한다. 배지에 hover하거나 포커스하면 답변을 가리지 않도록 배지 아래에서 해당 원문을 미리 보고, 키보드와 마우스로 PDF 위치로 이동할 수 있어야 한다. 응답 문장과 검색 청크 사이의 위치 정보가 없으면 문장별 인용 표시를 추측해 붙이지 않는다.

## 사용자 시나리오

1. **질문하기**: 보조 패널을 열고 입력창에 질문을 쓴 뒤 Enter를 누르면 대화 내역에 질문이 추가되고, 잠시 후 답변이 스트리밍으로 나타난다.
2. **페이지 이동 중 이어 묻기**: 답변을 읽다가 다음 페이지로 이동한 뒤 새 질문을 보내면, 이전 대화는 그대로 남아 있고 새 질문은 이동한 페이지를 기준으로 응답한다.
3. **실패에서 복구**: 응답 생성이 실패하면 오류 안내와 재시도 버튼이 나타난다. 재시도하면 같은 질문에 대한 응답을 다시 받는다.
4. **좁은 화면에서 사용**: 화면이 좁아 패널이 Sheet로 열린 상태에서도 질문 입력·전송·대화 내역 확인이 잘리거나 겹치지 않는다.

## 완료 기준

- **SC-001**: 질문을 입력하고 Enter를 누르면 대화 내역에 질문이 추가되고 응답이 스트리밍으로 순차 표시된다.
- **SC-002**: 응답을 받는 동안 새 질문 전송이 비활성화되고, 완료되면 다시 전송할 수 있다.
- **SC-003**: 응답 실패 시 오류와 재시도가 제공되고, 재시도하면 같은 질문에 대한 응답을 다시 받는다.
- **SC-004**: 페이지를 이동해도 대화 내역이 유지되고, 새 질문은 이동한 시점의 페이지를 기준으로 응답한다.
- **SC-005**: 키보드만으로 질문 입력·전송·대화 내역 탐색이 가능하고, 스크린 리더로 로딩과 응답 갱신을 확인할 수 있다.
- **SC-006**: 320px 화면 폭과 좁은 화면 Sheet에서도 채팅 조작부가 겹치거나 화면 밖으로 잘리지 않는다.
- **SC-007**: 텍스트가 있는 페이지에서 질문하면 값이 있는 도서 메타데이터와 해당 페이지 번호·본문이 모델 컨텍스트에 포함되고, 다음 페이지로 이동한 뒤 질문하면 이전 페이지 본문 대신 새 페이지 본문이 포함된다.
- **SC-008**: 한국어 답변 지시와 문장 완결 지시가 모델 컨텍스트에 포함된다.
- **SC-009**: 한 페이지에서 여러 OCR 줄에 걸친 문장을 선택해 `채팅에 추가`를 반복하면 줄 순서를 보존한 여러 인용문이 입력창 위에 줄바꿈 가능한 블록으로 표시된다. 각 인용문은 따로 제거하거나 질문과 함께 보낼 수 있다. `자세히 설명`을 누르면 채팅 패널이 열리고 첨부한 모든 인용문과 설명 질문이 즉시 전송된다.
- **SC-010**: 인용문이 없는 새 대화에서 `이 페이지 요약`을 누르면 현재 페이지 본문을 기준으로 한 요약 질문이 전송된다.
- **SC-011**: 다운로드 완료 후 GPU 로딩·실행 준비를 다운로드로 표시하지 않는다. 캐시가 완전하면 채팅 패널을 열기 전부터 모델을 준비하고, 캐시가 없거나 불완전하면 다운로드 버튼을 누르기 전까지 엔진을 생성하지 않는다.
- **SC-012**: 여러 페이지의 검색 청크를 사용한 답변은 생성이 끝난 뒤 답변 하단에 각 페이지의 인용 출처 배지를 나란히 표시한다. 각 배지 아래의 미리보기에는 해당 청크 본문이 보이고, 이동을 선택하면 해당 페이지·줄 범위로 이동한다.

## 가정

- 채팅 UI는 assistant-ui 라이브러리(Base UI 플레이버)를 기반으로 구현하며, 이에 따라 상태 관리 라이브러리 `zustand`를 도입한다. 세부 구성은 `plan.md`에서 다룬다.
